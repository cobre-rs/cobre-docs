**Status:** action plan (research complete, no edits made yet).

## 0. TL;DR

v0.14.0 is a **large, breaking release** — ~96 commits across 6 crates
(`cobre-sddp` 173 files, `cobre-io` 82). It carries **two headline features** and a
long tail of breaking renames:

1. **Generalised policy graph** (SDDP.jl-style nodes/transitions) generalising the
   implicit stage chain — the biggest conceptual addition; needs new math-layer
   content.
2. **Post-study "right boundary"** — carries and prices in-transit water and
   anticipated-thermal commitments that mature _after_ the study horizon. **This
   entire feature is absent from the CHANGELOG.** It also makes a long-standing
   documented limitation ("volume maturing past the last stage is dropped") _stale_.

Plus: an exact/deterministic upper bound + `gap` stopping rule; a generic-constraints
authoring-language overhaul; an output-schema canonicalisation (axis renames, node
axis, new files); a breaking policy-checkpoint format change + new Python writer; and
windowed anticipated commitments.

**Scale of the doc work:** ~40 distinct file actions, incl. **2 new pages**, **1
tooling fix that blocks vendoring**, a schema re-vendor, and ~6–8 new diagrams. Six
files are edited by multiple verticals and **must land as coordinated batches** (the
repo's no-propagation-registry rule).

**Do not start editing until the v0.14.0 tag is cut** — field names on `develop` can
still move, and the build needs a committed tree.

## 2. Cluster A — Policy graph & scenario structure

**What changed (ground truth).** `stages.json` gains an optional `policy_graph.nodes[]`
(each `{id, stage_id, scenario_id?, label?}`) and `policy_graph.transitions[]`
(`source_id`/`target_id` become node ids once `nodes[]` is non-empty; each carries a
`probability`). A deck with no `nodes[]` is a stage chain **byte-for-byte as before**.
The engine is a finite/acyclic/leaf-terminated policy graph in the **SDDP.jl family**
(Dowson 2020): each non-leaf node owns its own future-cost pool (Benders cuts); the
backward pass aggregates successors weighted by transition probability; the forward
pass samples a root→leaf trajectory.

- **Two probability axes** (cobre `docs/design/graph-probability-and-discount-semantics.md`):
  between-node edge weights (normalised to sum 1 at load) and within-node openings.
  Discount is a **separate per-stage** factor — `stages[].annual_discount_rate_override`;
  a _per-edge_ override is **rejected** under `nodes[]` (moved from `transitions[]`).
- **`policy_graph.type`**: `finite_horizon` only; **`cyclic` is reserved → rejected**
  at load with a named error.
- **Selection overhaul (breaking):** `training.selection` = `sampled{forward_passes}` |
  `enumerated{}`; `simulation.selection` = `sampled{num_scenarios}` | `enumerated{}`.
  Per-stage **`num_scenarios` → `num_openings`**. The root `training.forward_passes`
  and flat `simulation.num_scenarios` aliases are **removed**; `selection` is the sole
  home. Missing `training.selection` is now a hard load error.
- **Three external-scenario Parquet files** (`scenarios/external_{inflow,load,ncs}_scenarios.parquet`,
  one row per `(stage_id, scenario_id, entity_id)`) with strict loader rejection of
  1-based/gapped `scenario_id` sets, out-of-range stages, and disagreeing per-stage
  counts. `training.scenario_source.openings = {"source":"file"}` reads
  `noise_openings.parquet` and **conflicts** with `nodes[]` and with enumerated
  selection.
- **`state_space.inflow_lag_depth`** — new lag-state control (continuous PAR lag, not a
  Markov lattice).
- **Enumerated forward selection** computes the exact bound and requires a _structural
  tree of single-realization nodes_: `|Ω_n| = 1` per node and in-degree 1 (no
  recombination); a `K^T` fan is guarded by checked arithmetic (overflow → setup error).
  Sampled selection has neither restriction.
- **Known limitations** (cobre `docs/design/policy-graph-limitations.md`): single
  initial node (no uncertain initial regime); single terminal value shared across
  leaves; finite-horizon only.

> ⚠️ **Naming correction:** the cobre design note still says `realization_id`; the
> **shipped field is `scenario_id`**. Document `scenario_id`. (Report the stale note
> upstream — see §9.)

## 3. Cluster B — Exact upper bound, `gap` rule, census simulation

**What changed (ground truth).**

- **Exact deterministic upper bound** `UB = Σ_ℓ P(ℓ)·C(ℓ)` over every enumerated
  root→leaf path (Neumaier-compensated, bit-reproducible); std and CI are **exactly 0**
  (an enumeration is not a sample). Contrast the existing statistical/Monte-Carlo UB.
- **`gap` stopping rule REPLACES the removed `simulation` rule.** `gap = max(0, UB_exact − LB)`;
  fires on `gap ≤ tolerance` **or** relative arm. **Two breaking changes**: the relative
  gap is now normalised on **|LB|** (was |UB|), and `relative_tolerance` is now in
  **PERCENT** (`0.01` = 0.01 %) — a 100× reinterpretation.
- **Admission gate:** the `gap` rule is admissible only under **enumerated** forwards
  **and** an **expectation** measure at every stage (named errors otherwise;
  `CVaR{λ=0}` counts as expectation).
- **`training/convergence.parquet`:** `upper_bound_mean` → **`upper_bound`**; NEW
  **`upper_bound_kind`** (`"exact"`|`"statistical"`); `upper_bound_std` now **nullable**
  (NULL on every exact row). Metadata gains `final_upper_bound_kind`.
- **Census (enumerated) simulation:** exact weighted mean + weighted **population**
  variance (no Bessel); NEW `simulation/scenario_summary.parquet`
  (`scenario_id`, `probability` nullable/census-only, `discounted_immediate_cost`).
  `SimulationSummary` **reduced** to `{mean_cost, std_cost, n_scenarios}` — `cvar`,
  `cvar_alpha`, and min/max/deficit placeholders **removed**.
- **Doc correction:** `best_upper_bound` stores the **last** iteration's UB, not a
  min-tracked best.

## 4. Cluster C — Generic-constraints authoring overhaul

**What changed (ground truth).**

- **`sense` removed; shape derived from bounds.** A constraint is `{id, name,
description?, expression, slack}`. `generic_constraint_bounds.parquet`'s single
  `bound` becomes nullable **`bound_lower`/`bound_upper`**: lower-only ⇒ `>=`, upper-only
  ⇒ `<=`, both-equal ⇒ `==`, both-differing ⇒ a **range** (one constraint, not the
  v0.13.0 two-constraint pair). Shape labels: `floor|cap|equality|band`.
- **Two-sided slack:** a two-sided slack row gets two slack columns; reported
  `slack_value` is the **signed net** `s⁺−s⁺`, cost charges **both**.
- **Named `expressions`** (`@name`): declare a linear combination once, reference by
  `@name` (cycle-detected, scale-distributed, ≤100k inlined terms). The `@name`
  namespace is **shared** with scalar parameters.
- **Inline relational RHS** (`lhs <op> rhs`) normalised onto the interval; affine
  remainder + parenthesis grouping; **folds additively** onto the parquet base.
- **Activation-grid rule (user-facing gotcha):** the bounds parquet **is** the activation
  grid. An inline-bound constraint with **no rows** is rejected; a both-NULL row is legal
  **iff** an inline affine remainder is present.
- **Per-(stage,block) parameter axis:** 5th kind **`per_stage_block`** + `block_values`.
- **File relocation (breaking):** `system/scalar_parameters.json` →
  **`constraints/generic_parameters.json`** (top-level JSON key stays `"scalar_parameters"`).
- **`line_exchange(source_bus=X, target_bus=Y)`** — net line flow by bus pair (orientation
  sign folded).
- **`generic_constraints/resolved_echo.parquet`** (13 cols, always written when the study
  has generic constraints) — the flat desugared form the solver sees.
- **Legacy column removals (breaking):** `external_ncs_scenarios` `value`→`availability_factor`;
  `penalty_overrides_ncs` `source_id`→`ncs_id`; `pumping_bounds` `station_id`→`pumping_station_id`.

## 7. Cluster F — Post-study boundary + windowed commitments + hydro bounds

**What changed (ground truth). The post-study boundary is a new feature absent from the
CHANGELOG.** A rolling/DECOMP-shaped study decides in-study but _delivers after_ the last
dispatch stage. Two things previously **lost at the horizon edge** are now carried and
priced against a **terminal boundary future-cost function**: (a) anticipated-thermal
commitments maturing past `T`; (b) water in transit on a travel-time arc maturing past `T`.
Post-study stages are **boundary-only** — never dispatched, never cut; a deck with no
boundary is byte-identical.

- **NEW `post_study_stages.json`** (+ `post_study_stages.schema.json`): post-study stages
  (`start_date`, `duration_hours`) + per-`(thermal, post-study-stage)` cost/min/max bounds.
  First `start_date` must equal the study horizon end (date-contiguous).
- **Water travel-time right boundary:** when a terminal boundary FCF is present, the deep-lag
  terminal in-transit slots are **kept live and priced** (`β·x`) rather than dropped. Emits
  a rolling seed (`transit_seed/`) for a follow-on run.
- **Windowed `past_anticipated_commitments` (BREAKING):** `{thermal_id, values_mw:[...]}` →
  `{thermal_id, start_date, end_date, value_mw}` dated windows tiling the lead. NEW
  `future_anticipated_deliveries` (`{thermal_id, delivery_start, delivery_end, min_mw, max_mw}`)
  — in-study-decided, delivered after the horizon.
- **Boundary reconciliation:** dated hour-weighted fan-out (Blend/Renormalize); a report on
  `cobre run` and `cobre validate --json`; `policy.boundary.source_stage` is now **optional**
  (auto-resolved).
- **Hydro diversion floor + spillage band** (additive, per-`(stage,block)` columns on
  `constraints/hydro_bounds.parquet`): `min_diversion_m3s`, `min_spillage_m3s`,
  `max_spillage_m3s`. A diversion floor requires a declared diversion channel.

> ⚠️ **Stale limitation text:** `lp-formulation.md` §5d and `system-elements.mdx` both state
> "in-transit volume maturing after the last stage is **dropped** … a deliberate limitation."
> With a terminal boundary FCF this is now **conditionally resolved** — must be rewritten (the
> drop is preserved only _without_ a boundary; deeper-than-horizon travel time remains a limit).

## 11. Proposed execution sequence (once v0.14.0 is tagged)

The batched-edit rule means the natural unit is **one PR per cluster**, with two shared-file
PRs sequenced deliberately. A workable order:

1. **PR-0 (prerequisite):** tooling fix + schema re-vendor (§8) — unblocks everything that
   references a schema.
2. **PR-1 (cluster C):** new `reference/generic-constraints.mdx` + constraints edits + legacy
   column renames (self-contained authoring surface).
3. **PR-2 (cluster A):** new `math/policy-graphs.mdx` + stages.json + selection + scenario
   structure.
4. **PR-3 (cluster B):** exact bound + gap rule + census (depends on A's selection vocabulary).
5. **PR-4 (cluster F):** post-study boundary + windowed commitments + hydro bounds + new
   boundary chapter.
6. **PR-5 (cluster E):** checkpoint format + Python.
7. **PR-6 (cluster D + the shared `output-format.mdx` batch):** absorbs every vertical's
   output-schema edits into one coordinated pass, last, so all column-count bumps land together
   and the `check:counts` gate stays green.

Each PR runs the full gate set on a committed tree: `check:links`, `check:math`, `check:voice`,
`check:version`, `check:counts`, `npm test`, `npm run build`.
