# Doc-lint baseline allowlist.
#
# Grandfathers pre-existing hits of the doc gates that read it, so each gate
# fails on every NEW violation while a hit under editorial review stays
# recorded with its rationale. The readers:
#   - check-doc-voice.mjs      (npm run check:voice)
#   - check-doc-version.mjs    (npm run check:version)
#   - check-doc-narration.mjs  (npm run check:narration)
#   - check-glossary.mjs       (npm run check:glossary)
# check-doc-counts.mjs does not read this file: a stated column or field count
# that disagrees with its adjacent table is a plain factual error, with no
# grandfather path.
#
# Format: one entry per line, `<relpath>:<line>  <rule-id>  # rationale`.
# `<relpath>` is relative to src/content/docs/ and `<line>` is the 1-based line
# of the hit. Blank lines and lines starting with `#` are comments; a malformed
# entry fails the gate by name.
#
# Reading: an entry grandfathers only the rule it names, and only for the gate
# that owns that rule. Each gate reports every one of its own entries that
# matches no hit as STALE and fails, so a line shift fails on both sides: the
# unlisted hit at its new line and the entry left at the old one. The reader
# is scripts/doc-lint-allowlist.mjs.
#
# Removing an entry: reword the prose it grandfathers and delete the entry in
# the same change. An edit that only shifts the line re-keys the entry in that
# change.
# Adding an entry: only for a genuine exception under review, with a rationale
# that names the exception. New prose is fixed at the source, never listed
# here. The voice gate also accepts an inline `<!-- doc-voice-ok: reason -->`
# marker on the line of a real exception.
