---
title: Troubleshooting
description: The cause and fix for each failure a study meets while loading a case, loading a policy, solving, launching under MPI, and preparing scenarios.
---

Each table maps a failure you see to its cause and to the change that clears it. The exact message text lives on [Error Codes](/reference/error-codes/), and the exit codes on [CLI Reference](/reference/cli-reference/#exit-codes); every row links the entry that owns its message.

## Load and validation errors

| Symptom                                                                                                                                                                                            | Cause                                                                                                                                                                                                                                                                                                        | Fix                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `unknown field` in `config.json`; exit `1`; [message](/reference/error-codes/#parseerror)                                                                                                          | `config.json` holds a key that the object around it does not accept, such as a misspelt name or a field that belongs to another stopping-rule `type`.                                                                                                                                                        | Remove or correct the key against [Configuration](/running/configuration/). The message gives the line and column.                         |
| `a forward-pass count is required`; exit `1`; [message](/reference/error-codes/#schemaviolation)                                                                                                   | `training.selection` is absent. The key is required even when `training.enabled` is `false`.                                                                                                                                                                                                                 | Add `training.selection`; see [`training.selection`](/running/configuration/#trainingselection).                                           |
| `required field is missing` on `training.stopping_rules`; exit `1`; [message](/reference/error-codes/#schemaviolation)                                                                             | `training.stopping_rules` is absent. The key is required even when `training.enabled` is `false`.                                                                                                                                                                                                            | Add a rule set with at least one rule; see [`training`](/running/configuration/#training).                                                 |
| `unsupported factor_pivot_threshold` (or another solver-profile field); `cobre run` exit `1` after `cobre validate` passed; [message](/reference/error-codes/#solver-profile-validation) | A per-phase override (`training.solver.backward`, `training.solver.forward` or `simulation.solver`) is checked against the compiled solver backend when the study is built. `cobre validate` builds the study only when `policy.boundary` is set, so it passes the case. A CLP build refuses every override. | Set the field within the range the message names, or remove the override; see [`training.solver`](/running/configuration/#trainingsolver). |

Admission rules for the `scenario_source` blocks report one failure at a time, in code order, so fixing one message can reveal the next: rerun `cobre validate` until it passes. The rules check `simulation.scenario_source` as well as `training.scenario_source`, and they check it even when `simulation.enabled` is `false`. The rule table is in [Scenario-source admission rules](/reference/error-codes/#scenario-source-admission-rules).

## Policy load refusals

| Symptom                                                                                                          | Cause                                                                                                                                                              | Fix                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `policy was written by cobre`; exit `1`; [message](/reference/error-codes/#policyversionmismatch)                | The checkpoint's `manifest.bin` records a cobre version other than the running one. The comparison is exact.                                                       | Train the policy again with the running version, or re-export it under that version; see [Version gate](/running/policy-management/#version-gate). |
| `stored basis for node`; exit `1`; [message](/reference/error-codes/#storedbasisdimensionmismatch)               | A stored LP basis does not fit the stage LP it would warm-start, for example after a change of block mode, block count or entity set alters the LP's column count. | Retrain the policy on the study that loads it; see [Stored-basis gate](/running/policy-management/#stored-basis-gate).                             |
| `Policy directory not found`; exit `4`; [message](/reference/error-codes/#how-a-policy-load-failure-reaches-you) | No checkpoint exists at `policy.path`, resolved against the output directory. A first run killed before training ended leaves none.                                | Point `policy.path` at the checkpoint, or train first; see [Policy Load Contract](/running/policy-management/#policy-load-contract).               |
| `failed to read policy checkpoint`; exit `4`; [message](/reference/error-codes/#how-a-policy-load-failure-reaches-you) | The checkpoint at `policy.path` cannot be read, for example a directory without `manifest.bin` left by a job killed while it wrote its checkpoint (the write removes the previous checkpoint first). | Train again with `policy.mode` `"fresh"`, or point `policy.path` at a complete checkpoint; see [Checkpoint Directory Contents](/running/policy-management/#checkpoint-directory-contents). |

`cobre validate` never opens `policy.path`, so a case that passes it can still meet these refusals under `cobre run`. Both commands read a `policy.boundary` checkpoint.

## Solver failures

| Symptom                                                                                       | Cause                                                                                                                                               | Fix                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `LP infeasible at scenario`; exit `3`; [message](/reference/error-codes/#simulation-failures) | A stage LP of a simulation scenario has no feasible solution. `cobre validate` does not solve stage LPs, so it accepts such a case.                 | Read the scenario and stage in the message, then check the constraint bounds at that stage, such as hydro minimum and maximum storage that conflict. [Penalty System](/math/penalty-system/) lists which constraints are soft.                                                                                                                         |
| `Training failed after`; exit `4`; [message](/reference/error-codes/#solver-failures)         | A stage LP of a training iteration failed, for example an infeasible subproblem. Training stops and writes partial outputs to the output directory. | For an infeasible subproblem, the `training error:` line names the stage, iteration and scenario (stage and scenario are 0-based); check the constraint bounds at that stage. [Penalty System](/math/penalty-system/) lists which constraints are soft. A `training error: solver error:` line carries a solver message, which the linked entry lists. |

## MPI runs

| Symptom                                                                                                                                                                         | Cause                                                                                                                                                                                   | Fix                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| The `Execution` banner prints once per rank, and its line `Layout:    {world_size} {rank_word} on <host>` reads `1 rank`; [diagnosis](/running/hpc-deployment/#troubleshooting) | The processes did not form one MPI job: each initialised MPI as its own one-rank job.                                                                                                   | Follow the diagnosis and rebuild steps in [HPC Deployment](/running/hpc-deployment/#troubleshooting). |
| `pmijobid missing in fullinit command`; [diagnosis](/running/hpc-deployment/#troubleshooting)                                                                                   | An MPICH built for PMIx has no PMI-2 client, so `srun --mpi=pmi2` cannot launch it. An incompatibility between SLURM's PMI2 plugin and MPICH's PMI2 wire protocol gives the same error. | Launch with `srun --mpi=pmix`; see [HPC Deployment](/running/hpc-deployment/#troubleshooting).        |
| `same --threads value`; exit `4`; [message](/reference/error-codes/#solver-failures)                                                                                            | The ranks of one job started with different `--threads` values, and the backward pass detects it.                                                                                       | Start every rank with the same `--threads` value.                                                     |
| `'mpi' is not available in this build`; exit `4`; [message](/reference/error-codes/#communication-failures)                                                                     | `--comm-backend mpi` is set on a binary built without MPI support; `cobre version` prints `comm: local`.                                                                                | Run the `cobre-mpi` binary under an MPI launcher; see [HPC Deployment](/running/hpc-deployment/).     |

## Stochastic preparation refusals

`cobre validate` reports the first three rows as `StochasticPreparationError`, exit `1`, only when it builds the historical library; [Historical-library refusals](/reference/error-codes/#historical-library-refusals) states when it does.

| Symptom                                                                                                                                                | Cause                                                                                                                                 | Fix                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `V2.1: stage`; exit `4` under `cobre run`; [message](/reference/error-codes/#historical-library-refusals)                                              | A study stage has no `season_id`: it declares none, and the season definitions are absent or leave its start date uncovered.          | Assign a `season_id` to every study stage.                                                                                                                                             |
| `V2.3`, `non-finite eta`; exit `4` under `cobre run`; [message](/reference/error-codes/#historical-library-refusals)                                   | A hydro has a zero seasonal standard deviation and a historical observation that differs from its mean, or the fit fails numerically. | Supply history equal to the hydro's mean, or a non-zero standard deviation.                                                                                                            |
| `no valid historical windows found`; exit `4` under `cobre run`; [message](/reference/error-codes/#historical-library-refusals)                        | No start year has history that covers the required seasons, so the window pool is empty.                                              | Supply history that covers the required seasons for at least one start year.                                                                                                           |
| `openings source is 'file'`; exit `1` under `cobre validate`, exit `2` under `cobre run`; [message](/reference/error-codes/#opening-tree-file-missing) | `training.scenario_source.openings` is `{"source": "file"}` and `scenarios/noise_openings.parquet` is absent.                         | Place the tree at `scenarios/noise_openings.parquet`, or declare `{"source": "generated"}` or no `openings` so Cobre generates it; see [`training`](/running/configuration/#training). |
