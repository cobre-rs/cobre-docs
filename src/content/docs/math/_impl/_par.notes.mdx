Non-normative software behavior for PAR(p) estimation — what Cobre does at
runtime, beyond the equations above. This tab references the methodology
body for the derivations rather than restating them.

### `std_m3s` vs `sigma_m`

The two files in the Inputs & Outputs tab store two different standard
deviations, and the software surface never conflates them: `std_m3s` (column
in `inflow_seasonal_stats.parquet`) is the **stored sample standard
deviation** of the historical series for a (hydro, season) — a fixed,
on-disk number. `sigma_m`, the residual standard deviation that scales the
stochastic innovation term, is never stored directly; it is **computed at
runtime** from `std_m3s` and the residual std ratio `r_m`, which Cobre always
derives from the AR coefficients via the periodic-ACF closure rather than
reading it from a stored column (methodology §3). Reading `std_m3s` as if it
were `sigma_m` — or vice versa — silently rescales every noise draw.

### Legacy `residual_std_ratio` values are silently corrected, not merged

When a legacy `inflow_ar_coefficients.parquet` supplies its own
`residual_std_ratio` alongside AR coefficients, Cobre does not average,
validate-and-keep, or merge the stored value with the closure derivation — it
replaces the stored value outright and emits one deprecation warning per file
(see the Inputs & Outputs tab). Two worked corrections from Cobre's own test
fixtures show the range of the resulting shift:

- A directly-supplied AR(1) coefficient $\psi^* = 0.5$ (uniform order 1
  across every season it uses) with a stored ratio of `0.85` — never fit
  against $\psi^*$ — is corrected to the closure value
  `0.866025403784439` ($\sqrt{1-0.5^2}$), a gap of about `1.6e-2`.
- A directly-supplied AR(2) model (structurally uniform order across both
  hydros, coefficients $\psi^* = [0.5, 0.3]$ and $[0.4, 0.2]$) with a stored
  ratio of `1.0` for both hydros — likewise never fit against $\psi^*$ — is
  corrected to `0.667618...` / `0.848528...`.

Both corrections land on a **uniform**-order case, so the derived value is
exact (not the fitted-mixed-order drift described below) — the correction
size in each case reflects only how far the stored literal was from being
consistent with $\psi^*$ in the first place, which is unbounded: a stored
value can be arbitrarily inconsistent with its accompanying coefficients, so
the shift is not confined to a small numeric band the way the fitted-drift
class below is.

### Golden-value drift for internally-fitted models

A model **fitted internally** by Cobre (not a directly-supplied legacy file)
can also see its derived `r_m` shift relative to what the pre-closure
Yule-Walker computation would have produced, but only under one condition and
by a much smaller margin: when per-season AR orders differ across the
periodic cycle (a mixed-order fit), the closure-derived value differs from
the old per-season Yule-Walker value by roughly `1e-4`, localized to the
season(s) at the fit's maximum order. A **uniform**-order fit (every season
sharing the same AR order) matches the old value to double precision
(about `1e-12`) — the closure and the direct Yule-Walker computation are the
same system in that case. This mixed-order gap is theoretical; no end-to-end
test fixture currently exercises it (contrast the directly-supplied
corrections above, which are demonstrated end-to-end).

### Model-quality diagnostic: explained variance

The low-residual-variance model-quality warning now reports an
`explained_variance` field ($R^2 = 1 - r_m^2$) instead of the raw ratio,
firing under the same numerical condition as before
($R^2 > 0.99 \Leftrightarrow r_m^2 < 0.01$, methodology §6). It is a
library-surface diagnostic type only: Cobre computes it internally and does
not render it on the CLI or expose it through the python bindings. Keep this
reframed $R^2$ distinct from `r_squared`, the *residual* (unexplained)
fraction reported in the stationarity gate's own rejection message (see the
Inputs & Outputs tab) — the two are inverse quantities describing different
situations: `explained_variance` is a quality signal on an accepted model,
while `r_squared` in a rejection message is the reason a model was rejected
outright.

### Order-selection behavior

The classical PACF order-selection rule (methodology §4.1) and the
Maceira & Damázio iterative reduction it triggers are applied automatically
whenever Cobre estimates from `inflow_history.parquet`. Two runtime details
sit alongside that rule but are not part of the derivation:

- **`min_observations_per_season` is a warning, not a load-time error.** When
  a (hydro, season) group has fewer historical observations than the
  configured value (default 30), Cobre logs a model-quality warning naming
  the plant and season and proceeds with the fit anyway. The threshold is a
  quality signal, not a hard gate.
- **`max_coefficient_magnitude` is an independent safety net.** When set and
  any fitted coefficient for a (hydro, season) exceeds the threshold in
  magnitude, Cobre clears that group's coefficients entirely (order reset to
  0) and resets its `residual_std_ratio` to `1.0`. This runs as a separate
  pass from the Maceira & Damázio contribution-chain reduction (methodology
  §4.1) — a coefficient can trigger this magnitude cutoff even when its
  composed contribution is non-negative.

### History classification runs before any order selection

Before PACF selection sees a (hydro, season) bucket, the history
classification pipeline (methodology §5.7) runs automatically: constant,
saturated, and negative-dominated series are detected and, for the first two,
routed to a degenerate order-0 fit rather than left to over-fit a
structurally uninformative bucket. This classification is unconditional —
it always runs when estimating from history, on both the classical PAR(p)
and PAR(p)-A paths.

### PAR(p)-A annual-component runtime behavior

Setting `order_selection: "pacf_annual"` (Configure tab) extends the
estimation pipeline with the steps of methodology §9. At runtime this adds
one requirement not visible in the equations: a hydro needs **at least 13
chronological observations** to participate in PAR(p)-A — the minimum to
form one rolling 12-month average (§9.3). A hydro with fewer observations on
the PAR(p)-A path is a **hard estimation failure**; there is no silent
fallback to the classical path (methodology §9.7).

### Determinism guarantee

PAR(p) fitting is one of the model families covered by Cobre's
order-stable parallel fitting guarantee: coefficients are fit independently
per hydro and reassembled into a canonical per-hydro slot, so the fitted
model is a function of the inputs alone — independent of how many threads
run or how hydros are distributed across them. See
[Determinism Guarantees §3](/math/determinism-guarantees) for the full
mechanism, which this chapter's estimation pipeline shares with the
computed-FPHA fitting pipeline described in
[Hydro Production Models](/math/hydro-production-models).
